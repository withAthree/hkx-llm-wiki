# llm-wiki-lint

LLM-Wiki 的健康检查工作流。当用户要求检查知识库状态时触发。

## 触发条件

**命令触发：** `!wiki lint`
**自然语言触发：**
- 「我的知识库健康状况如何」
- 「检查知识库状态」
- 「检查健康」
- 「跑个 lint」
- 提及要检查 wiki 健康状况

## 核心规则

**仅读扫描。** 报告前禁止修改、删除、重命名任何文件。

**修复前必须确认。** 生成报告后等用户确认再执行修复。

## 步骤

### 1. 扫描所有 wiki 页面
扫描 `wiki/` 下所有 `.md` 文件（排除 `index.md` 和 `log.md`），含动态子目录。

### 2. 检查索引完整性
- 读取 `wiki/index.md` 中注册的所有条目
- 扫描实际存在的所有 `.md` 文件
- 比对：找出已注册但文件不存在的条目 → 死条目
- 找出文件存在但未在 `index.md` 注册的 → 未同步索引

### 3. 检查死链
扫描所有 `.md` 文件中的 `[[wikilink]]`：
- 找出指向不存在的页面的链接
- 记录来源页面和目标页面

### 4. 检查孤页
统计所有 `.md` 文件的被引用情况（排除 self-reference）：
- 排除 `index.md` 和 `log.md`
- 找出从未被任何其他页面引用的页面

### 5. 检查未解决的知识冲突
- 全局搜索所有 `.md` 文件中包含 `## 知识冲突` 标记的页面
- 扫描 frontmatter `related` 字段中的 `rel: contradicts`
- 统计带未解决冲突的页面（认知技术债）

### 6. 生成报告

```
## 🩺 知识库健康体检报告 — YYYY-MM-DD

### ✅ 绿灯项
- [运行良好的项目]

### ⚠️ 黄灯项
- **发现 N 个孤儿页面**：[列表] - 建议添加关联或分类
- **发现 N 个未同步索引**：[列表] - 文件存在但未在 index.md 注册

### ❌ 红灯项
- **发现 N 个死链**：[来源页面] → [[不存在的目标页面]]
- **存在 N 个未解决的知识冲突**：[页面名称]

### 🛠️ 下一步行动
1. 是否需要自动修复未同步索引？
2. 是否需要针对知识冲突进行重新推演？
```

### 7. 记录日志
无论是否发现问题，在 `wiki/log.md` 追加：

```
## [YYYY-MM-DD] lint | 扫描报告

- 死链：N 个
- 孤页：N 个
- 索引未同步：N 个
- 未解决冲突：N 个
```

### 8. 等用户指令
用户确认后再执行修复。

### 9. 修复后记录
修复完成后在 `wiki/log.md` 追加：

```
## [YYYY-MM-DD] lint | 修复完成

- 修复：死链 N 个、孤页 N 个、索引未同步 N 个
- 冲突处理：N 个
```

## 约束
- 报告前不修改任何文件
- 修复前必须等用户确认
